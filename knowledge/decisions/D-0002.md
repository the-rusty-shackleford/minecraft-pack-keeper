# D-0002 — Kept packs are fixed in position, and a listed pack for another game version is accepted on the player's behalf

**Decision**: The kept packs are handed to the game with
`PackSelectionConfig(required=true, TOP, fixed=true)`, not `fixed=false`
as D-0001 had it. And any kept pack whose metadata the game judges
incompatible is added to `Options.incompatibleResourcePacks` before the
game reads the list.

**Why**: Both came out of the first trial on the real modpack (thirteen
packs, a fresh `options.txt`). When the game builds the selection it
inserts every required pack it finds missing from the saved list at the
top, alphabetically -- so NeoForge's own `mod_resources`, absent from a
fresh player's list, landed above every kept pack, and the mods' textures
beat the resource packs meant to replace them. With the kept packs fixed
at TOP, the game's insertion walks back past them and puts a later
required pack beneath the block, which is where the shipped `options.txt`
always had it. Second, "Fresh Food" declares pack format 46; the game
drops an incompatible pack from the saved list unless the player has
accepted it, then re-adds it as required -- on top. Listing a pack in the
modpack's config is that acceptance, so the mod records it the way the
player's own click would.

**Consequences**: The game does not save fixed packs into the options
list, so the kept packs are absent from `options.txt` between launches and
are imposed afresh each time -- which is what the mod does anyway. In the
pack screen the kept packs cannot be moved; a pack the player adds goes
on top of them and can be moved among the player's own.

**Alternatives rejected**: *Naming `mod_resources` in `Selection.imposedOn`*
— covers one pack; any mod registering a required pack would land on top
the same way. *Leaving incompatible packs to the player* — the modpack
author already decided, and the game's own recovery put the pack in the
wrong place.
