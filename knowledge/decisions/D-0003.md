# D-0003 — Files a player should start with are seeded once from `config/packkeeper/seed/`, at mixin bootstrap, never overwritten

**Decision**: Anything under `config/packkeeper/seed/` is copied to the
same path under the game folder on launch where nothing exists yet, and
never touched again; a path that would leave the game folder is refused.
The copy runs from a mixin config plugin's `onLoad` -- a mixin config
with no mixins in it -- because that is the earliest hook a mod gets,
before the game's `Options` are built. The planning is pure
(`domain.Seeding`), the copying is `Seeder`.

**Why**: Rusty: "whenever we load the latest modpack, it replaces our
existing shader settings". The pack shipped his Complementary settings
file under `overrides/shaderpacks/`, and a launcher reapplies every
override on every update; the Modrinth format has no "only if missing".
He wants newcomers to start with his settings and everyone else to keep
their own. Iris reads `iris.properties` from a mixin into `Options`
(`MixinOptions_Entrypoint` calls `Iris.onEarlyInitialize`), which runs
before any mod constructor -- a seed made from the constructor would
have taken effect on the second launch. The plugin runs earlier.

**Alternatives rejected**: *Seeding from the mod constructor* -- too
late for Iris by one launch. *A ModLauncher transformation service* --
heavier for the same moment. *Leaving it to the players* -- the ask was
that a new player starts with the pack's shaders on.
