# Named distance updates run once for existing and new players

Rusty requested shared client distances without overwriting friends' preferences,
approved applying the update once to everyone, and clarified 24 chunks with
200% Entity Distance Scaling. They can lower the values afterward.

An optional `options_update` object in `packkeeper.json` names an id and exactly
two vanilla values: render distance and entity distance scaling. The existing
bootstrap plugin applies it after seeding, before Minecraft loads options. The
JDK-only text transformation replaces only those keys and preserves every other
character; values and the receipt filename are validated.

Each id reserves a local receipt directory before modifying options, preserves
the original file when present, replaces options through a temporary file, and
records completion. Completed and interrupted reservations never replay. This
favors preserving later player choices if a process or filesystem fails between
writing options and recording completion. The log identifies incomplete attempts;
manual inspection can decide whether to retry. Receipts and backups must never
be shipped in overrides. Pack authors retain the same id across ordinary updates.

Whole-file overrides would reset unrelated preferences. Existing seed semantics
cover only missing files and cannot update current players. Enforcing distances
on every launch would prevent players accommodating their hardware. Neither is
the approved behavior. Seeding and resource-pack ordering remain separate.

Verification uses partition-driven JUnit tests against real temporary files,
plus two real client launches: initial migration, then changes saved through
Minecraft and preserved on relaunch. No server gametest applies to this
client-only feature.
